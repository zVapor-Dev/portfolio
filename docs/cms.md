# Payload CMS runbook

This portfolio is a Next.js App Router app with Payload CMS mounted at
`/admin`. Public pages render CMS content when Postgres is reachable and fall
back to static content from `src/lib/fallbacks.ts` when the database is missing,
empty, or unavailable.

## Runtime map

| Surface | Codepath | Notes |
|---------|----------|-------|
| Admin UI | `src/app/(payload)/admin/[[...segments]]/page.tsx` | Payload admin, backed by the `users` auth collection. |
| Payload REST API | `src/app/(payload)/api/[...slug]/route.ts` | Generated by Payload's Next integration. |
| Public content loader | `src/lib/content.ts` | Reads the `site` global plus `projects`, `technologies`, and `experience`. |
| Live preview | `src/app/(frontend)/next/preview/route.ts` | Requires `PREVIEW_SECRET` and an authenticated Payload user. |
| Seed route | `src/app/(frontend)/next/seed/route.ts` | Authenticated admin-only POST endpoint. |
| CLI seed | `src/seed/run.ts` | Local API seed for development or one-off operator use. |
| Contact API | `src/app/api/contact/route.ts` | Uses SMTP through `src/lib/email.ts`; returns 503 until SMTP is configured. |

## Required environment

Set these variables locally in `.env.local` and in the deployment platform:

| Variable | Required | Used by |
|----------|----------|---------|
| `DATABASE_URL` or `POSTGRES_URL` | Yes | Payload Postgres adapter and seed scripts. |
| `PAYLOAD_SECRET` | Yes | Payload auth/session signing. Use a stable random value per environment. |
| `PREVIEW_SECRET` | Yes for preview | `/next/preview` validation. |
| `NEXT_PUBLIC_SERVER_URL` | Yes in production | Payload live-preview URLs and public metadata. |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `CONTACT_TO` | Yes for contact form | `POST /api/contact`. |

`SMTP_PORT` defaults to `587`, `SMTP_SECURE=true` enables TLS-on-connect, and
`SMTP_FROM` falls back to `SMTP_USER`.

## Content model

- `site` global: hero, about, contact copy, email, and social links.
- `projects`: selected work. Public rendering only includes documents where
  `published` is `true`, sorted by `order`.
- `technologies`: stack entries sorted by `order` and grouped by category in the
  UI.
- `experience`: work-history entries sorted by `order`.
- `users`: Payload admin users.

The public loader returns fallback content if the `site` global is missing its
name or all three content collections are empty. This keeps the site buildable
and viewable before CMS data has been created, but it also means an empty
database can hide missing production content during smoke tests.

## Schema changes

Payload is configured in `src/payload.config.ts` with:

```ts
push: process.env.NODE_ENV !== 'production'
```

That means development can sync schema changes automatically, but production
does not push schema updates during `npm run build` or `npm run start`. This
branch does not include Payload migration files, so operators must ensure the
production database schema is created or updated before deploying model changes.

When changing fields or collections:

1. Update the collection/global config in `src/collections/*` or
   `src/globals/*`.
2. Run `npm run generate:types` so `src/payload-types.ts` matches the schema.
3. Update `src/lib/content.ts`, frontend components, and `src/seed/data.ts` for
   any fields used publicly.
4. Test locally against a disposable or development Postgres database.
5. Plan the production schema update before deploying, because production `push`
   is disabled.

## Seeding

There are two seed entry points:

```bash
npm run seed
```

and an authenticated admin request from a logged-in browser or session:

```bash
fetch('/next/seed', { method: 'POST' })
```

Both seed paths update the `site` global, delete existing documents from
`projects`, `technologies`, and `experience`, then recreate those collections
from `src/seed/data.ts`. Do not run them against production unless replacing
CMS-managed portfolio content is intentional.

The HTTP route requires a logged-in Payload admin session. The CLI route uses
Payload's local API and requires a configured Postgres URL.

## Preview and fallback troubleshooting

- Preview requests return 403 unless `previewSecret` matches `PREVIEW_SECRET`
  and the request includes a valid Payload admin session.
- Collection live-preview URLs point to the homepage or section anchors using
  `NEXT_PUBLIC_SERVER_URL` when it is set.
- If public pages show fallback content, check that a database URL is present,
  Postgres is reachable, `site.name` is populated, and at least one public
  content collection has documents.
- If the contact form returns 503, set the SMTP variables listed in
  `.env.example`; builds do not require SMTP credentials.
